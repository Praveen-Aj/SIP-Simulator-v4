# SIP Inspector – SDP, Codecs, TLS/SRTP User Guide

This guide explains the new SDP / codec / TLS features added to SIP Inspector, and how to use them in practice.

---

## 1. SDP Tab – Codec and Profile Selection

### 1.1 Where to find it

- Open the **main SIP Inspector window** (after clicking `Next >>` from the first screen).
- In the bottom middle **ControlTabbedPane**, select the **`SDP`** tab (next to `SIP`, `Conditions`, `Commands`, `Variables`).

### 1.2 Controls on the SDP tab

The SDP tab lets you configure default SDP for all **generated** SIP messages (INVITEs and SDP responses created via the SIP tab).

- **Offer codecs (checkboxes)**
  - `G.711 (PCMA)`
  - `G.729`
  - `G.722`
  - `Opus`
  - You can select **multiple codecs**. These form the **offer** codec list in `m=audio` for INVITEs.

- **Preferred answer codec (combo box)**
  - Options: `G.711`, `G.729`, `G.722`, `Opus`.
  - This is the **single codec** used in **answers** (e.g. 200 OK with SDP) that SIP Inspector generates.
  - The preferred codec is always forced to be one of the **enabled** offer codecs:
    - If you uncheck the currently selected codec, the combo automatically moves to the first enabled codec.

- **Use SRTP (RTP/SAVP) (checkbox)**
  - When **unchecked**: SDP uses `RTP/AVP` in the `m=` line.
  - When **checked**: SDP uses `RTP/SAVP` in the `m=` line.
  - This affects both offers and answers generated by SIP Inspector.

- **Preview area (read‑only)**
  - Shows two sample `m=` lines based on your selections:
    - `// Offer (multi-codec)`
    - `// Answer (single codec)`
  - This is for visual confirmation only; it does not show the full SDP body.

- **Apply SDP settings (button)**
  - Saves your selections to the global settings used by the generator.
  - After clicking, new INVITEs and SDP‑bearing responses created via the **SIP** tab will use these settings.

### 1.3 What is actually generated (SDP details)

#### Offers – `getOfferSDP()`

- Used for **INVITEs** generated by the SIP tab.
- Audio line:
  - `m=audio [media_port] RTP/AVP ... 101` or `RTP/SAVP` if SRTP is enabled.
- Payloads:
  - `G.711 (PCMA)` → payload **8**, `a=rtpmap:8 PCMA/8000`.
  - `G.729` → payload 18, `a=rtpmap:18 G729/8000`.
  - `G.722` → payload 9, `a=rtpmap:9 G722/8000`.
  - `Opus` → payload 111, `a=rtpmap:111 opus/48000/2`.
  - DTMF is always added last as payload 101 with:
    - `a=rtpmap:101 telephone-event/8000`
    - `a=fmtp:101 0-15`
- If **no codec checkboxes** are selected, SIP Inspector automatically falls back to **G.711 PCMA (8)**.

#### Answers – `getAnswerSDP()`

- Used for **SDP‑bearing responses** generated via the SIP tab (e.g. 200 OK, 183 with SDP).
- Uses the **Preferred answer codec** from the combo:
  - `G.711` → payload 8, `a=rtpmap:8 PCMA/8000`.
  - `G.729` → payload 18, `a=rtpmap:18 G729/8000`.
  - `G.722` → payload 9, `a=rtpmap:9 G722/8000`.
  - `Opus` → payload 111, `a=rtpmap:111 opus/48000/2`.
- Adds DTMF 101 as in offers.
- Uses `RTP/AVP` or `RTP/SAVP` depending on the SRTP checkbox.

#### Custom SDP override

- There is an advanced feature (`customSDP` in GlobalSettings) that, if set, bypasses the above logic and uses the custom SDP body **as‑is**.
- In normal usage, leave `customSDP` empty to rely on the SDP tab.

## 2. TLS and SRTP (RTP/SAVP)

### 2.1 Enabling TLS

On the **intro screen** (before the main window):

1. In **IP Connection Type**, select **`TLS`**.
2. Set the **Remote Server IP** and **Remote Server Port** (typically 5061 for TLS) in the Remote Server panel.

When you click the TLS radio button, SIP Inspector shows a reminder:

> TLS is selected as transport.
> If your server expects SRTP, please open the SDP tab and enable 'Use SRTP (RTP/SAVP)'.

This is just a reminder; it does not change any settings by itself.

### 2.2 Enabling SRTP (RTP/SAVP)

1. Go to the **SDP** tab.
2. Check **`Use SRTP (RTP/SAVP)`**.
3. Click **`Apply SDP settings`**.

From this point:

- All generated **INVITEs** and SDP responses will use `RTP/SAVP` instead of `RTP/AVP` in the `m=` line.
- The rest of the SDP (codecs, DTMF) is controlled by the codec checkboxes and preferred answer codec.

> For SRTP crypto attributes (`a=crypto`, etc.), use dedicated SRTP scenarios (for example, Template 14 in the enterprise template plan). Those templates carry explicit SDP with crypto lines.

## 3. SIP Tab – Responses with and without SDP

On the **SIP** tab (ControlTabbedPane → `SIP`):

- When adding a **response** message, the response combo box contains variants such as:
  - `180 Ringing`
  - `180 Ringing (SDP)`
  - `183 Session Progress`
  - `183 Session Progress (SDP)`
  - `200 OK (INVITE)`

Behavior:

- **`180 Ringing` / `183 Session Progress`** (without SDP):
  - Generated with `Content-Length: 0` and **no SDP body**.

- **`180 Ringing (SDP)` / `183 Session Progress (SDP)`**:
  - Generated with **SDP** using `getAnswerSDP()`.
  - Uses **Preferred answer codec** and the current `RTP/AVP` vs `RTP/SAVP` setting.

- **`200 OK (INVITE)`** (from SIP tab generator):
  - Always includes SDP via `getAnswerSDP()`.

This lets you quickly model early media and final answers with or without SDP, while keeping codec and transport behavior centralized in the SDP tab.

## 4. IP Address Semantics (From / To / Contact)

For **outgoing requests** generated by SIP Inspector (via `SIPMessageEntry`):

- **Request-URI and `To:` header**
  - Use **Remote IP** / `[remote_ip]:[remote_port]`.
  - Example:
    - `INVITE sip:155@[remote_ip]:[remote_port] SIP/2.0`
    - `To: <sip:155@[remote_ip]:[remote_port]>`

- **`From:` and `Contact:` headers**
  - Use **Local IP** / `[local_ip]:[local_port]`.
  - Example:
    - `From: <sip:1000@[local_ip]:[local_port]>;tag=...`
    - `Contact: <sip:1000@[local_ip]:[local_port];transport=[transport]>`

This matches the natural model:

- SIP Inspector = **caller** (local side, From/Contact).
- Call server = **callee** (remote side, To/Request-URI).

For **responses**, SIP Inspector uses placeholders like `[last_From:]`, `[last_To:]`, `[last_Call-ID:]`, etc., so responses always reflect the previous received message without extra configuration.

## 5. Built-in Scenario Behavior (PCMA, Not PCMU)

In `SIPInspector/trunk/scenarios/archive_default/`, the most-used built-in scenarios have been updated so that:

- All G.711 SDP now uses **PCMA** with **payload 8**:
  - `m=audio ... RTP/AVP 8 101`
  - `a=rtpmap:8 PCMA/8000`
- No G.711 **PCMU/0** is advertised in these built-in scenarios.

Updated examples include:

- `Call_client.txt`
- `Call_server.txt`
- `Call_xfer.txt`
- `xfer_referrer.txt`
- `xfer_target.txt`
- `Record_route_client.txt`
- `Record_route_server.txt`
- `Server_conditional_registration.txt`
- `PRACK_client_example.txt`

This keeps the built-in scenarios consistent with environments where PCMU is not supported, and aligns them with the SDP tab defaults.

> Raw customer/enterprise scripts under `Scripts/` are left as reference material and may still include PCMU. They are not used directly by the generator unless you manually load and run them as scenarios.

## 6. Quick Recipes

### 6.1 Outgoing call with PCMA only

1. Go to **SDP tab**.
2. Check **`G.711 (PCMA)`** only; uncheck other codecs.
3. Set **Preferred answer codec** to `G.711`.
4. Leave **`Use SRTP (RTP/SAVP)`** unchecked.
5. Click **`Apply SDP settings`**.
6. Use the **SIP** tab to generate an `INVITE` and responses, or run a built-in scenario like `Call_client.txt`.

Result: SDP offers and answers use only `PCMA/8000` (payload 8) for G.711.

### 6.2 TLS + SRTP + PCMA

1. Intro screen:
   - Select **`TLS`** as connection type.
   - Set Remote Server IP and Port (typically 5061).
2. SDP tab:
   - Ensure **`G.711 (PCMA)`** is checked.
   - Optionally enable other codecs (G.729, G.722, Opus).
   - Check **`Use SRTP (RTP/SAVP)`**.
   - Click **`Apply SDP settings`**.
3. Run your desired scenario (e.g. `Call_client.txt`) or use the SIP tab to create messages.

Result: All generated SDP uses `RTP/SAVP` with PCMA (payload 8) as the primary G.711 codec.
